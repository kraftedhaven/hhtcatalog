Summary
-------
This agent runs automated tests for the VisionRouter pipeline on a fixed schedule. It is
intended to run in a CI, cron container, or small VM and produce an append-only log
at `/logs/vision.json` for downstream alerting and dashboards.

Behavior details
----------------
- Frequency: every 15 minutes (cron or scheduler).
- Request: POST multipart/form-data with field `file` containing the test image.
- Expectations: successful HTTP 200 and a JSON payload that contains at least one of
  these keys: `vision`, `sku`, `pricing`, `seo`.
- Measurements captured:
  - timestamp (ISO 8601)
  - latency_ms (ms from request start to response received)
  - http_status
  - body_sample: truncated JSON response (for quick inspection)
  - fallback_detected: boolean (true when provider indicates fallback or low-confidence)
  - errors: list of error messages when present

Fallback detection heuristics
-----------------------------
- Response contains `fallback: true` or `provider: 'fallback'`.
- `vision` object missing expected keys (labels, text) when previous baseline had them.
- `sku` or `pricing` fields are empty, null, or include strings like "unknown", "n/a".
- Response time exceeds `FALLBACK_LATENCY_MS` threshold (default 3000ms).

Log format (one JSON object per line)
-----------------------------------
{
  "ts": "2026-08-20T10:00:00Z",
  "latency_ms": 1342,
  "http_status": 200,
  "fallback_detected": false,
  "body_sample": {"vision": {...}},
  "errors": []
}

Runner implementation (suggested)
--------------------------------
Create a small Node.js script `scripts/vision_qa.js` with these behaviors:

1. Read `process.env.VITE_PUBLIC_API_URL` and optional `VISION_API_KEY` and `FALLBACK_LATENCY_MS`.
2. Pick a test image (configurable path or rotating set in `tests/images/`).
3. POST form-data `file` to `${VITE_PUBLIC_API_URL}/analyze` with optional `Authorization` header.
4. Measure latency and parse JSON safely (catch parse errors).
5. Apply fallback heuristics to the response.
6. Append a compact record to `/logs/vision.json` (create the directory if missing).

Example minimal curl-based check (cron-friendly)
------------------------------------------------
curl -sS -w '\n%{http_code}\n%{time_total}' -o /tmp/vision_resp.json \
  -F "file=@tests/images/test1.jpg" \
  -H "Authorization: Bearer $VISION_API_KEY" \
  "$VITE_PUBLIC_API_URL/analyze" \
  | awk 'NR==1{resp=$0} NR==2{status=$0} NR==3{t=$0} END{print status,t}'

Deployment and scheduling
-------------------------
- Docker: build a tiny image that contains Node and the `scripts/vision_qa.js` runner and run it via a cron wrapper or systemd timer.
- Kubernetes: run a CronJob with schedule `*/15 * * * *` that executes the runner and stores results in persisted volume or pushes to an external logging endpoint.
- DigitalOcean App Platform: use a scheduled job or a small Droplet with a cron entry.

Permissions & security
----------------------
- The runner writes to `/logs/vision.json`; ensure the runtime user has write access.
- Keep `VISION_API_KEY` out of the repo; set it as an environment variable in the host or platform.
